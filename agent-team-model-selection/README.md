# Agent Teams: выбор модели и effort

Узкое обратимое расширение для **DSH 0.2.2-rc.1**. Меняет только два Host-модуля Agent Teams. Штатный Team UI, Remote Control, настройки, права и модель текущего Lead не меняются. ASAR приложения не редактируется.

## Использование

`spawn_teammate` получает необязательные `provider`, `model`, `reasoning_effort`:

```json
{
  "name": "designer",
  "description": "Дизайн и план",
  "prompt": "Подготовь дизайн и план; код не меняй.",
  "context": "fresh",
  "provider": "<id из list_team_models>",
  "model": "<точный id модели>",
  "reasoning_effort": "high"
}
```

`provider` здесь — **LLM provider**, не внутренний backend `spawn`/`fork`. Для просмотра разрешённых моделей и поддерживаемых effort используется `list_team_models`: без параметров — providers; с `provider` — модели; с `provider` и `model` — effort этой модели. Работают оба режима контекста: fresh и fork.

- `provider` и `model` задаются только вместе. Effort можно задать отдельно для наследуемой модели.
- Без этих полей сохраняется штатное наследование модели/effort.
- При смене модели без effort используется default новой модели, не effort Lead.
- Модель и effort проверяются до резервирования имени/слота участника. Неизвестные модели/effort отклоняются, не подменяются другими.
- Разрешения берутся из **существующей политики сессии**, как у штатных субагентов. Без сохранённой политики можно явно выбрать только текущую модель Lead. Список разрешённых моделей расширение не изменяет.
- Изменение выбора моделей в пользовательских настройках Subagent относится только к новым сессиям. Старые журналы не перепривязываются и не переписываются.
- `list_agents` показывает последнюю известную живую модель/effort. Для выгруженного участника неизвестная модель не подменяется моделью Lead.
- Возобновление использует штатный durable subagent descriptor; формат Team events и wire projection не меняется.

## Установка и откат

Устанавливать **только архив tgz** из `dist` через Plugin Manager, не каталог по `link:`. Архив физически устанавливается внутрь профиля; зависимости берутся штатным runtime resolver из комплекта DSH. У пакета нет install scripts, сетевых зависимостей или version exemptions.

Расширение отключает только штатные Host-записи `agent-team` и `tool-agent-team`, затем добавляет две заменяющие записи. Штатная запись `ui-agent-team` не меняется. Состав и конфигурация сверяются скриптом `scripts/verify-scope.mjs` с текущим профилем; при несоответствии установка должна быть остановлена. Значения Team config зафиксированы в patch и перед установкой должны совпадать с целевым профилем; это не автоматический перенос настроек оригинальных записей.

Устанавливать в состоянии покоя: замена сервиса штатно останавливает его живых участников. Если Plugin Manager требует restart, перезапустить приложение, а не запускать другой GUI. Для отката отключить или удалить этот bundle через Plugin Manager: вернутся оригинальные Host-модули. Поскольку Team-журнал не расширяется, отдельная миграция назад не требуется.

## Проверка

Исходные два модуля сохранены в `upstream` с SHA-256 и версией. Пакет публикует только реализацию, документацию и patch; исходные снимки и тестовые данные в tgz не включаются.

Офлайн-тесты используют библиотеки именно установленного DSH через отдельный процесс Electron с `ELECTRON_RUN_AS_NODE=1`. Тестовый loader не нужен при штатной установке архива в профиль.

```powershell
$env:ELECTRON_RUN_AS_NODE='1'
$env:DSH_TEAM_TEST_RUNTIME='<абсолютный путь к app.asar/dsh>'
# Только для проверки состава профиля; задайте целевые каталоги явно:
$env:DSH_PROFILE_DIR='<абсолютный путь к целевому профилю>'
$env:DSH_HOME='<абсолютный путь к домашнему каталогу DSH>'
& '<путь к DeepSeek Harness.exe>' --import ./scripts/runtime-loader.mjs --test tests/selection.test.mjs
& '<путь к DeepSeek Harness.exe>' --import ./scripts/runtime-loader.mjs scripts/verify-scope.mjs
# После установки:
& '<путь к DeepSeek Harness.exe>' --import ./scripts/runtime-loader.mjs scripts/verify-scope.mjs --after
```

Покрытие: fresh/fork, наследование, allowlist/отсутствие политики/повреждённая политика, неверные маршруты и effort, смена модели, отмена и смена backend, параллельные участники, truthful roster, реальная схема и execute инструментов, совместимость Team events/projection и task DAG.

**Граница доказательства:** LLM-adapter и native admission в тестах заменены безопасными fixtures. Используются реальные штатные helpers для слияния AgentOptions и subagent descriptors. Это не реальный вызов провайдеров/моделей, не полная проверка native cold resume и не browser-click тест.
