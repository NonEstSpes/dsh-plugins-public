# Совместимость выпусков 0.1.2–0.1.5

В0.1.4 было добавлено только объявление `remote`, чего оказалось недостаточно для traced namespace. В0.1.5 явно объявлены `remote` и `remote.commands`, а доступ к `commands.execute` проверяется в реальном Client apply до регистрации панели. Исправлена также распаковка RPC `RemoteResult<CommandExecution>`: сначала `{ok,value}`, затем `value.result`. Добавлены проверки успешного RPC, отказа транспорта, ошибки команды и некорректного результата. Host-протокол, ключи и Worker state не меняются; достаточно обновления Controller и свежей загрузки страницы.

Целевая версия DSH: **0.2.2-rc.1**. Ограничение `engines.dsh` остаётся точным; version exemptions не требуются и не предоставляются. Предыдущий выпуск 0.1.1 остаётся предназначенным для DSH 0.2.1-rc.5.

## Изменения адаптера

- Удалённые вызовы `sessionController.inspect` заменены на `sessionQuery.readSession`.
- `SessionLogSnapshot.session` передаётся как заголовок в проверку cwd и восстановление проекций; `events` и `inheritedEventCount` сохраняют прежнее назначение.
- Регистрация проекции ожидается через `await sessionProjections.register(...)` до публикации команд, инструментов и подписчиков.
- Live-состояние читается через полученный `ProjectionHandle.stateOf(session)`, без deprecated keyed registry reads.
- Слот composer dock, локализация, результаты команд, scoped tool restrictions/guards, sandbox policy и поля native prompt сверены с контрактами/исходниками установленного DSH 0.2.2-rc.1.

## Что не меняется

Протокол relay остаётся версии1. Pairing keys, IDs, bearer tokens, endpoint-конфиги и каталоги состояния сохраняются. Relay на VPS и Tuna обновлять для этого перехода не нужно. Повторно запускать pair или очищать журналы нельзя только ради обновления плагина.

Для нового развёртывания предпочтителен одинаковый выпуск0.1.3 на обоих ПК. Выпуски0.1.2 и0.1.3 используют один транспортный протокол; автономный помощник можно запустить без переустановки0.1.2. Перед обновлением сохранить конфиги/журналы в закрытом пользовательском каталоге; после него проверить абсолютный `settingsFile`. Не распаковывать с удалением всего старого каталога: там могут находиться `.private` и состояние. Архив плагина этих данных не содержит.

## Граница проверки

Автоматический набор проверяет relay, шифрованный транспорт, доменный движок, Host-адаптер и сквозную loopback-доставку с fake native backend. Host-регрессии покрывают cold/live redaction, новые формы session snapshot/registration handle, запрет чужой сессии и сменившегося проекта, scoped guards и отсутствие agent-инструмента для reload/выдачи wake-согласия.

Эти тесты и проверка API не заменяют реальную приёмку с Worker на рабочем Windows-ПК, модельным провайдером и Tuna. Первую задачу выполнять в demo-проекте без инструментов; публикация, shell и запись файлов по-прежнему не входят в этот этап.
