# Native federation v2

Эта спецификация описывает native SessionSource-канал Bridge, а не старый агентский MVP. Сборка пакета не означает его применение или визуальную проверку GUI. Для полного исправления ответов после мутаций обновляется Bridge на Worker; обновление только Controller не меняет код старого Worker.

## Согласование и совместимость

Базовый `protocol:2` сохраняется. Controller отправляет прежний `hello` с точными пустыми аргументами `{}`. Авторизованный Worker может добавить в результат `features`, например `['model-catalog-pages-v1']`. Отсутствие поля означает legacy, а не неявную поддержку. Корректные неизвестные версии игнорируются; неверные типы, дубли и чрезмерный манифест отклоняются. Манифест ограничен 32 именами по 64 ASCII-символа.

Возможность описывает реализованный формат, но не выдаёт полномочий. Каждая операция снова проверяет authenticated pair, актуальный grant, проект, native Session и authority. Read-only каталог не требует и не включает mutation readiness. Для мутаций по-прежнему нужны точный Worker helper и свежий авторизованный ответ в текущем lifetime Controller.

При явной загрузке каталога Controller заново получает `hello`; одновременные читатели делят этот запрос, но отмена одного читателя не отменяет остальных. Без объявленного `model-catalog-pages-v1` используется прежний `model.catalog`. Если объявленная новая операция отказана, незаметного downgrade или локального каталога нет. Старый Controller продолжает использовать старые операции; новая ответная metadata принимается прежним v2 envelope parser.

## Полный каталог через ограниченные страницы

`model.catalog.page` — read-only операция. Аргументы: `ref`, `expectedAuthority` и необязательный `cursor`; произвольные RPC, локальные пути и дополнительные поля не допускаются. `ref` содержит `machineKey`, `projectId`, `sessionId`. Перед чтением native модели проверяются session admission и project-level `model.list`.

Каждая страница содержит `scope`, `catalogId`, `default`, `start`, `totalRecords`, `records` и только при продолжении `nextCursor`. `scope` всегда содержит все пять полей: `machineKey`, `projectId`, `sessionId`, `generation`, `grantRevision`, в том числе на последней или пустой странице. Authority фиксируется Controller перед первой страницей и не подменяется между запросами.

Записи упорядочены: provider, его полные model-записи, следующий provider, затем failures. Provider содержит `type:'provider'`, `id`, `name`, `routable`; при `routable:true` обязателен `routableIndex`, иначе его нет. Индексы сохраняют самостоятельный порядок `routableProviders`, который может отличаться от порядка групп. Model содержит `type:'model'`, `providerId`, `model`. Failure содержит `type:'failure'`, `failure` с заранее заданным безопасным сообщением.

`catalogId` — SHA-256 нормализованного native ModelCatalog. Cursor `fmc1.` кодирует канонический tuple из полного scope, hash и следующего offset. Cursor не является разрешением и не заменяет проверку grant. Изменение моделей, default, authority или scope делает продолжение недействительным.

Controller проверяет плотную последовательность offset, неизменность default/hash/count/scope, порядки и уникальность записей, индексы routable, отсутствие небезопасных metadata и итоговый hash. Ошибка отравляет сборку; частичный каталог не публикуется. Итоговый immutable результат имеет обычные поля `default`, `routableProviders`, `groups`, `failures`; UI не собирает страницы самостоятельно.

Транспортные пределы не увеличиваются: полный federation envelope, включая metadata и wrappers, не превышает 32 KiB; существующие plaintext/ciphertext/HTTP пределы сохраняются. Runtime вычитает реальный response wrapper из бюджета страницы. Нормализованный каталог ограничен 4 MiB, 65 536 записями и 256 страницами; отдельная model-запись со всем списком effort неделима. Повторение длинного provider ID дополнительно ограничено суммарным wire-record бюджетом 256 × 32 KiB. Oversized запись даёт явный `page-too-large`, а не обрезанные effort или бесконечное продолжение.

Проекция экспортирует идентичность и названия моделей, все effort ID/названия и default effort. Описания, badges и сырые ошибки провайдеров, как и раньше, не экспортируются. Пустые группы и порядок групп, моделей и effort сохраняются; невалидные данные не превращаются в default Controller.

## Ошибки и неопределённые исходы

Source BFF сохраняет существующие классы ошибок. Сообщение содержит только allowlisted operation stage и стабильную причину: например `model.catalog.page: page-too-large` или `model.catalog: request-timeout`. Тексты статические и короче 200 UTF-8 bytes; исходные message/details/cause/пути/ключи/cookies не пересылаются. Неизвестный stage заменяется на `remote`, неизвестная ошибка — на безопасную недоступность.

Локальный deadline чтения отличается от отмены читателя; отмена не объявляется offline. Неверный коррелированный envelope, authority или op отклоняет pending read сразу, а не ждёт deadline. Невалидные project refs в ответе `catalog` отклоняются до публикации create admission и readiness.

Исход мутации после durable dispatch остаётся `outcome-unknown`, если потерян, повреждён или слишком велик receipt, изменился grant после эффекта либо не удалось записать результат. Ошибка после эффекта не является доказательством отсутствия эффекта. Controller не принимает поздний отказ во время reconcile как опровержение исходной неизвестной операции. Незавершённое состояние журнала блокирует новый ID для того же target; восстановление использует исходные ID и тело. Исключение — прежнее явное owner-only разрешение нового create после abandonment: оно не объявляет исход известным и навсегда запрещает replay старого ID. Только подтверждённый результат завершает неизвестную операцию; чтение каталога её не разблокирует.

## Ограничение чтений провайдеров

В private Worker API 0.1.2 подключён NON-Remote `sourceModelCatalog({providerTimeoutMs},signal?)` с `SourceCatalogReader`: explicit whole-provider deadline, параллельное чтение провайдеров, изоляция отказов, single-flight и quarantine. Штатные unbounded `buildModelCatalog` и публичный Remote `modelCatalog()` сохранены. Reader/default/registry listeners/disposal принадлежат контексту конструктора Service, не контексту его caller proxy.

Для включения Bridge 0.1.4 получает только из локальной plugin Config Worker поле `modelCatalogProviderTimeoutMs`: целое 1..60000 мс без неявного default. Его выбирает владелец ниже request deadline Controller; pairing JSON и удалённые аргументы на бюджет не влияют. Поле при Controller-role или v1 конфигурации отвергается. Без поля сохраняется прежний метод каталога; при явно запрошенном bounded-режиме старый, подменённый или отсутствующий helper даёт `action-unsupported`, а не unbounded fallback. После завершения чтения повторно проверяется владелец.

`ownsSourceCatalogHelper` независимо фиксирует точную реализацию нового метода и экземпляр приватного Worker пакета. Прежняя проверка восьми mutation-методов не изменена, и чтение не требует sandbox/mutation readiness. Bridge и Loader должны резолвить один физический helper 0.1.2; одинаковые имя/версия разных копий не заменяют тождество конструктора. Верификация staged resolver не является проверкой работающего профиля после установки.

Изменение локального бюджета инвалидирует текущие ожидания, но обновляет тот же reader и не удаляет quarantine незавершённых native-вызовов. Новые наблюдения используют новый бюджет; уже начатые не запускаются второй раз. События `llm/adapters-updated` и `llm/models-updated` инвалидируют reader; снятие owner fiber прекращает ожидания и удаляет listeners.

Native `llm.listModels` не имеет отмены. Deadline ограничивает ожидание, а не остановку такого I/O; quarantine удерживает незавершённый вызов до реального завершения, включая все metadata promises, и не накапливает новые вызовы при retry. Сигнал metadata resolver поддерживается, поздние результаты не публикуются. Полной отмены некорректного адаптера этот механизм не обещает.

## Подготовка native-details-v1 — browser-путь в исходниках, без активации

В исходниках есть закрытые serializers tool/call и tool/result: raw arguments сохраняются строкой, идентичность и разрешённый текст не меняются; metadata копируются только по проверенным схемам десяти native-инструментов. Неизвестные поля и небезопасные варианты редактируются либо скрываются с явным carrier redaction. Reasoning, файлы, бинарные данные и исполняемый interactive UI не экспортируются. Native assembler подтверждает соответствие assistant tool-call blocks и stream, порядок first-seen индексов и отфильтрованные компактные записи; второй assembler не создаётся.

`native-details-v1` отделён от legacy-истории: cursor `fec2.` включает формат и отвергается legacy follow; `fec1.` сохраняет прежние байты. Default provider bind остаётся legacy, а optional details face согласует точную Worker feature и не откатывает её отказ на legacy. Source BFF owner-only `bindDetails` захватывает `nativeDetails: true` в конкретном binding epoch; старый `bind` никогда не выбирает rich. Новый browser выбирает этот вызов только при BFF `supportsNativeDetails` и текущем Core readiness от реальных безопасных Tool/metrics Slot consumers. Снятие любого consumer синхронно отменяет owned/provisional adapters; guards дополнительно проверяют actual readiness перед вызовом, после await и перед frame. Обновление одного Host или одного Client-модуля не даёт согласия старой GUI на rich. В исходном candidate Worker объявляет SESSION_DETAILS в hello только при доступном `backend.readDetails` и разрешённой видимости машины, независимо от поддержки model catalog. Это не разрешение на данные и не mutation readiness. Настоящий Loader/HTTP/JWE/BFF/Client Session тест проверяет legacy bind на новом Worker, все четыре native projection values/watermarks на одном cut, очистку после issuer grant withdrawal и сохранение frozen sourceRef после revoke/dispose. Строгие отдельные Host/Client acceptance программы проходят без отключения проверок. Candidate не установлен и не активирован в профиле; это не физическая Worker или GUI-приёмка.

Метрики читаются из одного native sessionQuery observation вместе с header/events/cursor. Явные export classes: `statistics` для sessionStats, `usage` для tokenUsage, `context.metrics` для contextPressure/contextBreakdown. Только числовые wire views, не checkpoint или повторный fold; отсутствующие данные не заменяются нулями. Snapshot имеет тот же cut, а follow передаёт метрики только после достижения observation cursor; более новые totals не маркируются seq промежуточного batch. Полный frame остаётся ограничен 32 KiB, в том числе после замены native numeric versions на registration-scoped BFF tokens. Controller повторно проверяет scope и выбранный fec1/fec2 формат ответа; legacy не допускает Tool events или Tool blocks/runs даже от некорректного Worker. Новый SourceEventStream принимает numeric baseline через существующий ProjectionValueStore только в реальном journal publication callback после целого records batch и gap repair, затем подтверждает export cursor. Yield/resume и prefetch не считаются подтверждением; abort, retirement или policy change не публикуют метрики и не продвигают cursor.

Client исходники уже сохраняют immutable `SessionSnapshot.sourceRef` после удаления источника и направляют foreign root/subcalls в inert text/disclosure без локальных file/image/inspect/question/interactive действий. Для десяти reviewed native Tools добавлены закрытые structured metadata views: numbered read windows, applied old/new text, matches/paths/counts, web response/source facts и shell cwd; пути/URL/код остаются текстом, неизвестные и malformed формы сохраняют generic args/output. Статистика foreign сеанса использует только native projections, не неполный Chat window. Эти изменения ещё не собраны в новый общий пакет и не применены в GUI. В исходном candidate подключён отдельный live-путь; legacy/details bindings сохраняют includeAssistantStream=false. В установленной GUI эти изменения не активированы.

В исходниках Core есть отдельный NON-Remote `sourceFollow` с явными item/byte limits, constructor-owned identity, пассивным native opening и ограничением retained queue до/после snapshot. Новый [live projector](lib/federation/live-history.mjs) оставляет compaction/assembly настоящему native owner, фильтрует поля по grants, сохраняет first-close и raw arguments, выдаёт dense follow-local revisions/indexes и превращает подтверждённый withheld settlement в abandonment. Core Client повторно проверяет authority в actual publication отложенного live frame и не продвигает durable cursor от transient данных. [Native follow mapper](lib/federation/native-follow-history.mjs) связывает один physical iterator с scoped Source frames: opening сохраняет native header/cursor/projections/assistant cut, readDetails вызывается только для opening и durable events ради старого Tool context. Более новые numeric views не маркируются предыдущим cut; transient chunks не читают history заново. Source records с actual settlement выдаются до terminal, а withheld settlement становится abandonment. Runtime объявляет `native-assistant-stream-v1` только при полном native producer и успешно проверенном relay; binding остаётся явным. Реальная canonical Loader→Worker0.1.4→AgentLoop→Root HTTP/JWE→BFF bindLive→Client apply/registry/Session/Chat приёмка прошла для четырёх paced LLM text parts: видимость до durable Assistant message, настоящее settlement, четыре точных native numeric views на общем cut, held carrier withdrawal и immutable sourceRef до dispose. Это не проверка доставки640 независимых burst chunks и не assembled GUI acceptance.

Подготовлен immutable Worker helper0.1.4 с независимой проверкой exact SDK constructor/prototype, private instance-owned follow closure и захваченного static verifier; исходный eight-method mutation attestation, catalog verifier, Client/Remote/locale bytes сохранены. Сам адаптер предоставляет live reader/expand/compactor/assembler только при проверенном owner и отменяет все owned readers перед join. Source BFF имеет отдельный owner-only `bindLive`, captured `nativeLive:true` вместе с nativeDetails и includeAssistantStream; legacy/details вызовы никогда не выбирают live. Browser требует также actual Core `nativeAssistantStreamSupport:true` и текущие Tool/metrics consumers. Смена mode после await отказывает старой epoch; advertised refusal не становится fallback. Root provider.live подключён: первая handshake использует hello/bind.live, последующие BFF проверки используют bounded registration-owned receipt cache с exact ref/known authority и явным отказом metadataAuthorized=false. Receipt eviction требует новой handshake и не является anti-replay eviction; новые readers не исчерпывают cache навсегда. Перед каждым отправленным DATA проверяется current grant, включая synchronous guard после JWE encryption прямо перед HTTP POST.

Новый [derived-live HTTPS carrier](lib/live-channel.mjs) и отдельные relay `/v1/live/info`, `/v1/live/send`, `/v1/live/poll` используют JWE purpose `dsh-federation-live-v1`, pairing generation и reciprocal peer authorization. Это process-local at-most-once доставка, не mutation journal: relay restart, потеря ответа или carrier failure требуют rebaseline. TTL15s, bounded replay cache8192, mailbox256 сообщений/256KiB, исходный body32KiB и plaintext/ciphertext/HTTP caps59/80/100KiB; idle empty polls ограничены четырьмя в секунду. Durable endpoint, его anti-replay/outbox и журналы мутаций не изменены. External close отменяет network и переданный callback signal, затем join; callback должен завершаться по отмене и не ожидать `close()` своего carrier изнутри себя. Старый relay явно даёт unsupported до передачи live payload. [Credit/lease manager](lib/federation/live-stream.mjs) удерживает один Native.next и один неизменяемый DATA до следующего credit; retry того же индекса не создаёт второй native reader, heartbeat работает и при paused consumer, STOP/expiry оставляют bounded guards от delayed OPEN. ACK credit не подтверждает durable Source cursor. Runtime связывает manager с mapper/provider; проверены 640 text chunks одного synthetic producer с настоящими SDK compaction/readers и HTTP/JWE без новых durable endpoint messages. Отдельная actual native Loader/BFF/Client paced4 приёмка описана выше; Отдельная native pressure проверка также прошла:640 chunks генерируются независимо при paused consumer, AgentLoop завершает полный durable message, ограниченный reader безопасно отказывает без hang, а новый явный bind/physical follow восстанавливает точный native message/cut/метрики без нового prompt. Во время burst durable outbox не растёт; новая metadata handshake учитывается отдельно. Это не гарантия доставки640 chunks медленному active consumer. Это не измерение пропускной способности и не транспортная оптимизация; WSS не реализован. Первый положительный hello metadata proof при уже известных ТОЧНО тех же numeric generation/grantRevision теперь обновляет catalog, не отзывает собственный in-flight binding и не очищает подтверждённые project admissions; numeric/null/known-false changes и mutation readiness по-прежнему отзывают authority.

## Не включено этим изменением

Подробные tool payloads, statistics/live projections, динамические проекты, файлы/вложения и WSS ещё не объявляются реализованными возможностями. Нет нового агентского инструмента или ослабления Worker-политики. Тесты mock backend и loopback HTTP/JWE не заменяют native composition replay, проверку физического Worker, реального туннеля и Windows power-loss/ACL сценариев. Установка и визуальная проверка GUI остаются отдельными шагами.
