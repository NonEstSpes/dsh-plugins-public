# Переносимый native Worker 0.1.7-public.2

Пакет для **уже спаренной установки Worker с конфигурацией версии 2**: native-провайдер **0.1.7**, мост **0.1.6**. Это не установщик DSH/Node.js, не полностью офлайн-дистрибутив и не мастер нового устройства. Pairing v1 не мигрируется автоматически. Локальный Worker на Controller устанавливать и включать нельзя.

## Единственный канал доступа

**Не устанавливайте и не перезапускайте этот пакет через единственный работающий Worker без отдельно проверенного восстановления и явного согласования обслуживания.** Архив и процесс OpenCode на том же ПК не создают запасной сетевой канал. Если независимого восстановления нет, допускается только скачать архив, проверить контрольную сумму и подготовить план. Не запускайте две версии Worker на одном private stateDir.

Согласованная резервная копия активного состояния может требовать остановки. Не останавливайте единственный канал только ради backup. Нельзя обходить эту проблему изменением часов, grants, ключей, TLS, proxy, ревизий или удалением журналов. Статус relay/процесса не доказывает готовность Worker.

## Совместимость и исправление

Нужны **DSH 0.2.2-rc.1** и **Node >=24.9**; исключения совместимости не выдаются. Общий SDK предоставляет DSH, registry-зависимости могут требовать доступ к сети. Все файлы native SDK и генератор роли побайтно сохранены из проверенного Worker 0.1.7. Все файлы моста совпадают с опубликованным Bridge 0.1.6.

Bridge 0.1.6 использует бюджет **8192 исходящих записей** вместо прежних 512, сохраняя отдельный предел **256 pending**. Неистёкшие квитанции не удаляются, 24-часовое хранение не сокращается, HMAC и идентичности сообщений не меняются. Ёмкость конечна; постоянная высокая нагрузка всё ещё требует учёта бюджета. При заполнении выдаётся безопасная причина `local-outbox-full` или `local-inbox-full`, а не только общий текст недоступности.

**Downgrade:** JSON private store остаётся revision 2, но Bridge <=0.1.5 не читает outbox длиннее 512. После превышения границы сохраняйте новую версию либо выполняйте отдельно согласованное восстановление из совместимого backup с разбором последующих эффектов. Не обрезайте квитанции и не меняйте revision вручную. Формат native Session не изменён. Подробности: [UPGRADE.md](UPGRADE.md).

## Состав

- [Native SDK](native-sdk/package.json) и [Host-only Bridge](bridge/package.json).
- [Основной patch](cordis.patch.yml): Bridge выключен, без settings pointer.
- [Генератор роли](create-role.mjs): принимает путь к существующему локальному Worker v2 config, не читает его содержимое и не запускает DSH.
- [Манифест](build-manifest.json), [контрольные суммы](SHA256SUMS), [сведения о поставке](PUBLIC-RELEASE.md), лицензия upstream в `licenses/`.

В архиве нет ключей, токенов, конфигов пар, профилей, приватного state, пользовательских сессий, `node_modules`, тестовых данных или внутренней Git-истории. Скачивание и распаковка не активируют Worker.

## Согласованная установка локальным оператором

Следующие действия **не разрешены автоматически** из факта получения архива. Их выполняет оператор только при готовом независимом восстановлении.

1. Штатно остановить прежний Worker и сохранить согласованный защищённый backup существующей пары, полного private state и native-данных. Не передавать backup/конфиги в чат или git.
2. Через штатный Plugin Manager согласованно заменить прежние Worker/Bridge/role owners, не оставляя двух владельцев API. Не использовать горячие переключения core/UI owners, не редактировать профиль вручную, не заменять signed EXE/ASAR.
3. Распаковать архив в новый постоянный каталог вне профиля. Установить основной bundle штатным Plugin Manager по абсолютному пути к его `package.json`.
4. Для существующего Worker v2 config с неизменными identities, relay, ключами и grants создать отдельный role-bundle. Примеры с путями, которые оператор заменяет своими:

   ```powershell
   node .\create-role.mjs --settings-file "D:\WorkerConfig\worker-v2.json" --out "D:\WorkerBundles\native-worker-role"
   ```

   ```sh
   node ./create-role.mjs --settings-file /srv/worker-config/worker-v2.json --out /srv/worker-bundles/native-worker-role
   ```

   Родитель результата должен существовать, сам каталог результата — ещё нет. Генератор не читает настройки, не копирует секреты и отказывается перезаписывать существующий результат.
5. Явно установить role-bundle в тот же Worker profile. Только это действие включает Bridge с выбранным settings pointer. Сохранить прежний пользователя/launcher, proxy, CA и credentials. `pending`, `overridden` или `restart-required` не означают работающий Worker.
6. При согласованном запуске проверить фактические версии и свежий аутентифицированный ответ через существующую пару. Отдельно подтвердить чтение прежнего каталога/сессии. Health relay и успешная установка не заменяют эту проверку; неизвестные мутации нельзя повторять с новым id.

HTTPS остаётся default; WSS — явный opt-in с настроенными сроками подключения. Загрузка вложений требует уже live Agent; скачивание — точной ссылки в native USERLOG и текущих grants. Проектная регистрация принимает существующий путь, не создаёт OS-каталог и не присваивает старые сессии. См. [TRANSPORT.md](TRANSPORT.md).

Пакет подготовлен без установки на физический Worker. Целостность архива и проверки разработчика не являются доказательством WAN/TLS-доступности, power-loss recovery или готовности вашей удалённой машины.
