# Переносимый native Worker 0.1.7

Это устанавливаемый bundle для **удалённой машины с уже настроенным и спаренным Worker версии настроек 2**. Он содержит native-провайдер сессий 0.1.7 и мост 0.1.5. Это не установщик DSH/Node.js, не полностью автономный дистрибутив и не мастер первичного спаривания. Переход старой конфигурации спаривания v1 на v2 не автоматизирован.

**Не устанавливайте этот bundle в профиль Controller. Локальный Worker на машине Controller включать нельзя.** Проверки разработки не означают, что пакет уже установлен на вашей удалённой машине.

## Совместимость и состав

Нужны DSH **0.2.2-rc.1** и Node.js **24.9 или новее**. Не выдавайте исключение совместимости для другой версии DSH. Общий публичный SDK предоставляет DSH; его копии не включены в архив. Установка зависимостей использует обычный менеджер пакетов и может требовать доступ к registry.

Внутри находятся [native-провайдер](native-sdk/package.json), [мост](bridge/package.json), выключенный по умолчанию мост в [основном patch](cordis.patch.yml), [генератор роли](create-role.mjs), [сведения о транспорте](TRANSPORT.md), [заметки об обновлении](UPGRADE.md), [список хешей](SHA256SUMS) и [машиночитаемый манифест](build-manifest.json). Конфигурации пар, ключи, токены, данные сессий, профиль, node_modules и журналы приватного состояния не переносятся этим архивом.

## Установка на удалённой машине

**Сначала проверьте независимое восстановление. Не выключайте, не обновляйте и не перезапускайте единственный работающий удалённый канал без локального оператора или другого согласованного и проверенного способа доступа.** Если доступен только этот Worker, остановитесь: архив, доставленный через него, не обеспечивает восстановление после его остановки. Следующие шаги предназначены для локального оператора с готовым backup/rollback, не для автоматического самообновления через Worker.

1. Остановите старый Worker штатно и сохраните резервную копию полного приватного состояния, существующей конфигурации пары и native-данных сессий. Не удаляйте replay-записи и не меняйте номера версий вручную.
2. На **удалённой машине** через Plugin Manager выключите прежние Worker-, Bridge- и role-bundle, которые создают те же провайдеры или переопределяют их строки. Это предотвращает дублирование и скрытые overrides. Не удаляйте существующие данные пары и сессий.
3. Распакуйте архив в отдельный постоянный каталог вне профиля DSH. Через Plugin Manager установите bundle, указав **абсолютный путь к распакованному каталогу с основным package.json**. Не копируйте файлы поверх подписанной установки DSH и не редактируйте профиль вручную.
4. Основной bundle заменяет stock Session Controller native-провайдером Worker. Строка `remote-native-control-bridge` остаётся **выключенной**, без фиктивного settingsFile. Сам архив не содержит роли и не подставляет путь к настройкам.
5. Используйте существующий **worker-конфиг версии 2 на этой машине**. Проверьте роль Worker, адрес relay, соответствие пары, явные разрешённые проекты и grants. Не переносите Controller-конфиг на Worker. Пакет не создаёт и не расширяет разрешения.
6. Из распакованного каталога запустите генератор с абсолютными путями. Родительский каталог результата должен существовать; сам каталог результата — ещё нет. Пример для Windows, в котором оператор заменяет пути своими:

   ```powershell
   node .\create-role.mjs --settings-file "D:\WorkerConfig\worker-v2.json" --out "D:\WorkerBundles\native-worker-role"
   ```

   Для Linux используются абсолютные пути той машины:

   ```sh
   node ./create-role.mjs --settings-file /srv/worker-config/worker-v2.json --out /srv/worker-bundles/native-worker-role
   ```

   Генератор проверяет только существование обычного файла по заданному пути, **не читает его содержимое**, не копирует секреты и не запускает DSH. Он создаёт конфигурационный role-bundle с полным `config: { settingsFile: ... }`; существующий каталог не перезаписывает. Не создавайте role-bundle внутри профиля DSH.
7. Отдельно установите полученный role-bundle через Plugin Manager **в удалённом профиле Worker**. Только это явное действие включает мост с выбранным указателем настроек. Проверьте результат применения: `overridden`, `pending` и ошибка не означают работающий Worker. При замене уже загруженного пакета выполните требуемый DSH перезапуск.

## Транспорт и приватное состояние

По умолчанию сохраняется HTTPS. Для автоматического WSS задайте `relayTransport: "auto"` **на обоих концах пары v2** и явно выберите положительные целые `requestTimeoutMs` и `relaySocketConnectTimeoutMs`, причём время подключения не больше времени запроса. В HTTPS-only режиме поле времени подключения не задаётся. TLS-проверки не отключаются; разрешённый переход к HTTPS не меняет авторизацию. Подробности — в [документации проверенного моста](bridge/TRANSPORT.md).

Приватный endpoint-store revision 1 после полной проверки автоматически и атомарно обновляется до revision 2 с аутентифицированными компактными квитанциями. Pending-сообщения сохраняют исходный ciphertext и идентичность. Старые бинарники revision 2 не читают: нужен штатный backup/recovery, а не удаление состояния. Это **не** миграция старой версии конфигурации спаривания. См. [обновление моста](bridge/UPGRADE.md).

## Ограничения

Native-сессии, Assistant, Tools и метрики остаются данными Worker; модельные API не подменяются. Новый проект требует явного разрешения соответствующего шаблона GrantV2. Путь Worker вводится как путь его ОС, а не выбирается через локальный файловый диалог Controller. Файлы и изображения требуют явного класса экспорта `files` и соответствующих текущих разрешений чтения/отправки.

Загрузка принимает только **уже live** native Agent: холодная сессия не активируется ради вложения. Скачивание вложения разрешено только после появления его точной ссылки в пользовательском native-журнале этой сессии; draft-квитанция не даёт права на скачивание. Файлы передаются побайтно, изображения проверяет и нормализует SDK. Проверки EOF и текущего владельца не обходятся.

Реальные native Loader/SDK и loopback HTTP/JWE сценарии проверены разработчиком. Физическая WAN-сеть, реальный TLS-туннель, отключение питания и ваша удалённая установка этим архивом не проверены. Наличие архива или совпадение хешей не является подтверждением доступности Worker.
