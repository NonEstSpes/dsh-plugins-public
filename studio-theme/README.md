# Studio 1.0.0 — тема интерфейса DSH

Пакет: `@local/studio-theme`. Тег выпуска: `studio-theme@1.0.0`. Изменения перечислены в [истории версий](CHANGELOG.md).

Плагин добавляет в **Настройки → Общие → Внешний вид** выбор **Стандартная / Studio**. Установка и включение плагина не выбирают Studio: `design: default`. Пользователь самостоятельно выбирает тему; выбор сохраняется средствами настроек DSH, а светлый, тёмный и системный режимы продолжают работать.

## Что меняется

- Две тёплые нейтральные палитры: светлая и угольная тёмная, с терракотовым акцентом.
- 40 оригинальных SVG-иконок в двух весах: навигация, поиск, отправка, вложения, код, файлы, команды и статусы.
- Метка Studio в штатной ведущей области шапки; заголовок, вкладки, действия и меню не заменяются.
- Геометрия карточек, кнопок и поля ввода через токены радиусов; отдельные поверхности для кода, сообщений пользователя и навигации.
- Собственный знак темы в боковой панели и на пустом экране. Название приложения не меняется.

Вдохновение — спокойный desktop-чат и удобная работа с кодом. Чужие логотипы, шрифты, изображения и библиотеки иконок не используются. Оригинальные ресурсы распространяются под MIT.

## Совместимость и границы первой версии

Проверяемая версия DSH: **0.2.2-rc.1**. Плагин рассчитан на штатный интерфейс; совместимость с `@dsh-remote/native-session-bundle` следует проверять в целевой установке. Тема не меняет авторизацию, модель, разрешения, историю или удалённые сессии. Автоматически сгенерированная страница настроек скрыта, чтобы не дублировать выбор темы в Общих настройках.

Полную боковую навигацию, редактор ввода, сборку чата, карточки инструментов, правую панель и изменение ширины оставляем штатным поставщикам. Их приватные механизмы фокуса, caption-кнопок Windows, вложений, подтверждений и удалённых источников нельзя безопасно заменить одной темой. Поэтому первая версия не переносит проекты/историю/модель в другие части окна и не переписывает карточки инструментов: она меняет их оформление, иконки и дополняет шапку меткой. Это осознанное ограничение по сравнению с полным планом редизайна, а не скрытая CSS-перестановка чужого DOM.

## Выбор и возврат

1. Откройте Настройки → Общие → Внешний вид.
2. В «Тема интерфейса» выберите Studio. В «Цветовой режим» выберите светлый, тёмный или системный.
3. «Стандартная» возвращает прежний интерфейс и текущий встроенный цветовой режим.

Отключение плагина снимает его UI-регистрации, иконки и палитру. Если Studio была выбрана, текущая страница возвращается к сохранённому встроенному режиму; повторное включение плагина использует сохранённый выбор пользователя. На первой установке выбор всегда стандартный. При недоступных настройках активация не выполняется. Отказ записи отображается в настройках, а не выдаётся за успешное сохранение.

## Устройство

Host предоставляет единственное volatile-поле `design: default | studio`. Client читает его через `configForms`, регистрирует `studio-light` и `studio-dark` и активирует их только после принятого выбора Studio. Сторонние theme-id не записываются в встроенное поле `ui-theme.preference`, которое в этой версии принимает только `light | dark | system`. При системном режиме используется один освобождаемый media-query listener. Без опроса, внешних запросов, iframe, глобальных обработчиков клавиш или изменения установленного DSH.

Корневые слоты и существующие объявления дочерних слотов не заменяются: DSH разрешает затенение ячеек по приоритету, но запрещает повторно объявлять уже существующих детей. Метка регистрируется в существующем `conversation.header.leading`, не объявляя собственных дочерних слотов. CSS использует только собственные классы и токены. Ресурсы и подписки освобождаются при выгрузке; изменения цвета не перемонтируют чат или редактор. При сбое применения доступны «Подробности ошибки» с точным сообщением исключения.

## Проверки и сборка

Нужны Node.js 24.9+ и pnpm 11. Исходники находятся в `src/`. Генерируемый `client.js` не коммитится в Git, но входит в готовый пакет. Перед установкой из клонированного репозитория выполните в каталоге плагина:

```powershell
pnpm install --frozen-lockfile --ignore-scripts
pnpm run build
pnpm test
```

Сборщик esbuild зафиксирован в devDependencies и lockfile; `build.mjs` сам находит исполняемый файл для текущей платформы. При необходимости его путь можно передать явно: `node build.mjs <путь к esbuild>`. Запуск использует stdio inherit, без pipe-IPC. Локальная конфигурация pnpm использует плоские зависимости для совместимости с Windows junction-путями. Install-скрипты не запускаются.

После сборки каталог можно выбрать в Plugin Manager. Для получения отдельного пакета: `pnpm pack --pack-destination dist`. Архивы и временные проверки исключены из Git; готовый архив устанавливается без esbuild.

Проверки: `node --test --test-isolation=none tests/controller.test.js tests/package.test.js`, затем `python tests/check_svg.py`. Тесты проверяют отсутствие автоматического выбора, переключение режимов, выгрузку, восстановление при ошибках, метаданные и SVG. Они не являются проверкой реального рендеринга. Доступность Client-регистраций проверяется в установленном DSH. Без управления подключённым браузером внешний вид, клавиатура и узкое окно остаются визуально непроверенными.
