# Finance MVP API contract (implementation coordination)

Client: plain JavaScript lazy module `window.__ModuleLoader__.load({id:'@local/dsh-finance',factory(require){const React=require('react'); ... return {inject:['slots','locale'],apply(ctx){...}}}})`; React only, no Harness Client imports. Register new sidebar.panellist id `finance` order 20 label localised, main key `finance`, via ctx.slots.inject on each owner. Main has no Session props. Use host theme tokens only for UI colors; custom scoped CSS with own prefix. Localise visible text via ctx.locale.register('finance','ru',dict) and en dict + bind; use React.useSyncExternalStore for locale changes. No network outside same-origin plugin API. No client persistent storage of banking data. Safe native controls, focus/error semantics.

All calls: POST `/api/finance` credentials same-origin, headers Content-Type application/json, X-DSH-Finance: 1, body {action,args:{...}}. Returns {ok:true,value:...} or {ok:false,error:{code,message}} with HTTP error on failure. Abort outstanding reads on unmount. Host uses Connection requestRejection auth, Host/Origin checks. UI mutations explicit click/submit only. No bank login or n8n. Explicit advice.generate is the sole cloud-LLM exception: Host sends only whitelisted anonymized numeric aggregates to the configured OpenCode Go subscription, never raw statements/transactions or identity/recipient/account/note fields. No fallback model or automatic financial mutations.

Values: integer kopecks, RUB only. Localised display with Intl.NumberFormat. Dates YYYY-MM-DD, timestamps ISO. Free-text always rendered as text, never raw HTML. No destructive DOM-confirm hacks; use inline confirmation for reversing import. No demo records written to real DB automatically.

Actions (args -> value):
- `state` {month?:YYYY-MM,from?,to?,query?,needsReview?:bool,limit?:1..200,offset?:0,sortBy?:date|description|amountMinor|category|kind,sortDirection?:desc|asc} -> {accounts:[],categories:[],transactions:[],transactionTotal,imports:[],rules:[],incomeModels:[],goals:[],budgets:[],obligations:[],settings:{reportHour:21,timeZone:'Europe/Moscow',reportsEnabled:true},overview:{incomeMinor,expenseMinor,netMinor,unknownCount,count,totalCount,firstDate:null|string,categories:[],daily:[],insights:[],balanceMinor:null|number,latestDate:null|string,lastImportAt:null|string},reports:[],meta:{version:'0.1.14',currency:'RUB',rawStorage:'memory-only',dataDirectory:string,encrypted:false}}. Transactions {id,accountId,date,postedDate,amountMinor,description,counterparty,bankId,currency,category,kind:'income'|'expense'|'transfer'|'refund'|'loan',needsReview:boolean,note,sourceImportId}. Accounts {id,name,currency,openingBalanceMinor,openingDate,openingKnown,balanceMinor:null|number}. Categories {id,name,protected:boolean}. Imports {id,fileName,createdAt,fromDate,toDate,count,skippedCount,status:'committed'|'reverted',verification:'balanced'|'not_provided',netMinor,format}. Rules {id,label,counterparty?,descriptionContains?,minMinor?,maxMinor?,category,kind?,enabled}. Goals {id,name,targetMinor,savedMinor,monthlyMinor,deadline?,priority}. Budgets {id,category,limitMinor,protected}. Obligations {id,name,amountMinor,dayOfMonth,category,enabled}.
  - Sorting (0.1.10): `sortBy` defaults to `date`, `sortDirection` to `desc`; effective values are returned as `meta.sortBy` and `meta.sortDirection`. Only the listed fields and `asc|desc` are accepted (`INVALID_SORT` otherwise). The entire query/review-filtered set is sorted before offset/limit. Dates use ISO chronology; amounts use signed integer kopecks; text uses Russian natural collation, resolving category names and localized operation kinds. Equal keys retain repository date/rowid order. Sorting changes no records, totals or overview evidence order. UI resets offset to zero and toggles explicit clicks desc→asc→desc.
  - Default period (0.1.4): if no month/from/to is supplied, select the current Moscow month when it has committed operations, otherwise the latest available operation month. Explicit months/date bounds are never replaced. `meta.month`, `meta.from`, `meta.to`, `meta.monthSelection:'current'|'latest_available'|'explicit'` identify the effective period. `overview.totalCount`, `firstDate`, `latestDate` cover all committed history and exclude reversed imports; `overview.count` covers the date period; `transactionTotal` additionally applies search/review filters. Pagination changes none of these counts. UI accepts the effective server month on first load and focuses the imported transaction month after explicit commit.
- `account.save` {id?,name,openingBalanceMinor?,openingDate?,openingKnown?:bool} -> account.
- `category.save` {id?,name,protected?:bool} -> category.
- `import.preview` {accountId,fileName,base64?,csvText?,options?:{encoding:'auto'|'utf-8'|'windows-1251'|'utf-16le',delimiter:'auto'|';'|','|'\t',headerRow?:number},mapping?,openingMinor?,closingMinor?} -> {previewId,headers:[],sampleRows:[[]],mapping:{date,postedDate?,amount?,debit?,credit?,description?,counterparty?,bankId?,currency?,direction?,amountMode:'signed'|'debitCredit'|'direction'|'allExpenses'|'allIncome'},transactions:[],errors:[{sourceRow,message}],warnings:[],totals:{creditMinor,debitMinor,netMinor},period:{from,to},rowCount,duplicateCount,verification:'balanced'|'not_provided'|'mismatch',expiresAt,format:'CSV'|'PDF',extractedText?:string}. Column mapping values are INDEX numbers or omitted. Each preview transaction includes sourceRow,amountMinor,date,description,counterparty,duplicate:boolean. Preview must surface ALL row errors/count and cannot commit if errors or mismatch. At most first 200 preview rows returned, rowCount is full count. HeaderRow 0-based, UI can show 1-based. No server file persistence, only bounded memory preview (15min TTL).
  - Mapping recovery (0.1.2): missing required date/amount/direction columns returns a successful, editable preview with `mappingRequired:true`, `totals:null`, `period:{from:null,to:null}`, `verification:'not_calculated'` and errors `{scope:'mapping',field,code:'MAPPING_REQUIRED',sourceRow:null,message}`. Preserve headers/sampleRows. No ledger changes; commit rejects `MAPPING_REQUIRED`. A successful remap sets `mappingRequired:false` and computes totals. Do not display unknown totals as zero.
  - VTB account PDF (0.1.3): native seven-column grid extraction preserves multiline text and separates original FX amount from account `Приход`/`Расход`. Returns `pdfLayout:{id:'vtb-account-v1',pageCount,tablePages,sourceRowCount,checkedCoverage:true}`, `statementSummary:{openingMinor,closingMinor,creditMinor,debitMinor,currency:'RUB'}`, `statementVerification:'matched'|'mismatch'|'not_calculated'|'not_available'`. PDF controls initialize optional balances; remapping/overriding balances never disables mandatory PDF gross-turnover and balance reconciliation. Any mismatch blocks commit with `STATEMENT_MISMATCH`. Negative values in the explicitly labelled expense column become expense magnitudes with a visible warning; income and original FX signs are never flipped. Unrecognized generic PDFs retain the manual-review fallback. No raw PDF or real fixture is persisted.
  - VTB transaction commissions (0.1.8): optional exact bank label «Общая сумма транзакционных комиссий» yields signed `transactionFeesMinor`, `reportedDebitMinor`, and `feesAddedToDebit` in `statementSummary`. A declared negative commission is added to `debitMinor` only when the four bank controls do not balance without it and balance exactly with it; no double count when already included. No fee is inferred from a discrepancy or row totals. Positive nonzero, ambiguous, non-RUB or overflowing commission controls are rejected. Original transaction amounts/rows are unchanged and mandatory service reconciliation still applies.
- `import.remap` {previewId,mapping,openingMinor?,closingMinor?} -> same preview result with new previewId (old invalidated). Changes mapping without reuploading file.
- `import.commit` {previewId,includeDuplicateRows?:number[]} -> {importId,insertedCount,skippedCount,alreadyImported:boolean,rawDeleted:true}. Explicit user confirmation. Exact file/account repeat is idempotent. Potential duplicates excluded unless sourceRow explicitly included; UI warns. Original local Downloads file is untouched. Discard server preview and browser File/base64 state after success.
- `import.discard` {previewId} -> {discarded:true}; expire in memory as well.
- `import.reverse` {id} -> {reverted:true}; hides only that batch's imported rows, preserves audit/import records. Require inline explicit confirmation.
- `transaction.update` {id,category?,kind?,needsReview?,note?} -> transaction. Original bank fields immutable. Manual categorisation marks review false by explicit user choice.
- `rule.save` {id?,label,counterparty?,descriptionContains?,minMinor?,maxMinor?,category,kind?,enabled?:bool,applyExisting?:bool} -> {rule,matchedCount,updatedCount}; conditions literals (no regex), at least counterparty or description condition, amount absolute kopecks; no automatic category inference from generic transfer. User decides apply existing. Manual annotations protected from later rules.
- `income.save` {id?,name,effectiveFrom:'YYYY-MM',salaryMinor,workedRatio?:number,deductionsMinor?:number,payoutDay?:1..31,components:[{id,label,type:'fixed'|'percent_base'|'percent_running',value:number,multiplier?:number,guaranteed?:bool,enabled?:bool}]} -> {model,calculation}. All fixed amounts value=kopecks; percent value=%; sequential running dependencies, no eval. Variable premium not guaranteed. Model versions persist.
- Income v0.1.12 fields: model.taxRateBps optional integer0..10000 (13%=1300; absent preserves legacy zero); tax rounds gross*rate/10000 half-up in kopecks, deductionsMinor are additional post-tax deductions. Components accept frequency:'monthly'|'quarterly' (legacy monthly), explicit unique payoutMonths:[1,4,7,10] for quarterly, minValue/maxValue in the same units/base as value. Conservative/optimistic choose endpoints; base chooses value. Disabled/omitted components still validate. This is an explicit flat-rate assumption, not full progressive tax law. Save returns a cash calculation for effectiveFrom month; previous versions remain immutable.
- `income.calculate` {model,scenario?:'conservative'|'base'|'optimistic',month?:YYYY-MM,mode?:'cash'|'regular'|'average'} -> {grossMinor,taxMinor,taxRateBps,deductionsMinor,netMinor,components:[],warnings:[],mode,month?}. API defaults cash/current Moscow month; regular excludes quarters; average divides quarterly accrual by3 with exact rounding and is not available monthly cash. Reconciliation calculates the selected period in cash mode.
- `outlook` {modelId?,months?:1..12(default6)} -> six completed calendar history rows, source-range coverage, baseline, future full-month cash/savings projections, provisional explainable score and anonymized ai.payload preview. Missing expense periods are null, never zero. Full-range months with expense evidence are the preferred average basis; partial-only history is a lower estimate with warning. Excludes transfers/loans, counts unreviewed expenses conservatively, confirmed refunds only within their category/month. Baseline preserves the rounded total historical average and adds positive per-category current-plan top-ups; enabled plans are aggregated by canonical category ID/name against the same basis months. It is not history plus all obligations. baseline.plannedTopUpMinor and local categoryFloors explain increases (e.g. newly expensive subscriptions). No claim of confirmed operation-to-obligation matching; unknown categories and debt cashflows remain uncertain. Cash deficit and negative accumulated savings remain visible. Range coverage does not certify all-account completeness. Score uses regular net income, declared obligations and known liquidity, never anticipates quarter cash; not creditworthiness.
- `advice.generate` {modelId?,months?:1..12} -> locally cached {provider:'opencode-go',model:'deepseek-v4.1-flash',generatedAt,payloadHash,summary,savingsAdvice,aiScore:{value:0..100|null,reason,provisional:true},optimizations,warnings,groupLabels}. Subscription adapter via llm.prepareCall, low effort, no tools/fallback, 90-second timeout and unload cancellation. Only whitelisted aggregates and anonymous category group keys go outward. groupLabels stay local and preserve snapshot labels. No automatic financial mutations. Financial revision/model/payload changes mark snapshots stale; data changing mid-call rejects persistence.
- `income.reconcile` {modelId,period:'YYYY-MM',transactionIds:string[]} -> {id,expectedMinor,actualMinor,differenceMinor,period,transactionIds}. Selected actual POSITIVE income transactions can span payout dates/months. No double matches to different periods; only user selected. Persist result. state includes `incomeMatches` array with results.
- `goal.save` {id?,name,targetMinor,savedMinor,monthlyMinor,deadline?,priority?:number} -> goal. savedMinor manually tracked/reserved, NOT income.
- `budget.save` {id?,category,limitMinor,protected?:bool} -> budget.
- `obligation.save` {id?,name,amountMinor,dayOfMonth,category,enabled?:bool} -> obligation.
- `forecast` {modelId?,monthlyExpenseMinor?,balanceMinor?,months?:1..60} -> {scenarios:{conservative,base,optimistic},warnings:[]} each scenario {monthlyIncomeMinor,monthlyExpenseMinor,monthlyFreeMinor,overallocated,path:[{month,balanceMinor}],goals:[{id,remainingMinor,monthsToGoal:null|number,monthlyNeededMinor?,feasible}]}. If no known account balance -> require manual balance override (do NOT invent). In absence of provided monthly expenses use budgets total, else average of complete imported months only; warn incomplete coverage; no compounding/investment return. goal savings summed as reserved once, not counted twice.
- `report.generate` {period:'day'|'week'|'month',date?:'YYYY-MM-DD'} -> report {id,period,fromDate,toDate,createdAt,data:{...computeReport},freshness:{latestDate,lastImportAt},warnings:[]}. Stored versioned snapshot; no model call. Scheduler generates same deterministic reports at configured hour while Host alive, catches up latest periods on restart; no duplicate report key for unchanged data.
- `settings.save` {reportHour?:0..23,reportsEnabled?:bool} -> settings. No secrets.
- `export.csv` {from?,to?} -> {fileName,content} finance data export via explicit click browser Blob; CSV formula injection protected. No raw statement export.

First working UI should include actual empty-state/onboarding + account creation + CSV upload/mapping/preview/commit + operation list/category updates. Then income/goals/reports views within same source before final install if time allows. PDF extraction in parent backend; UI accepts CSV and PDF and mapping; display unsupported PDF layout errors honestly and encourage CSV. Never claim tested VTB layout without sample. Do not implement standalone page/iframe or browser auth/screenshot automation.
